# 📊 Mapa das Operações de Planejamento

Este documento resume como as ações do frontend (Zustand Store) se conectam às funções SQL do Supabase e o que cada uma faz.

---

## 🔹 Tabela de referência

| **Ação no Frontend (Zustand Store)** | **Função RPC no Supabase**             | **O que faz (lógica resumida)** |
|--------------------------------------|-----------------------------------------|---------------------------------|
| `fetchDadosComparativos`             | `planejamento_mensal_ipoupei_2025`     | Junta `planejamentos` (metas) + `transacoes` (realizado/pendente) + `categorias`/`subcategorias`. Retorna comparativo do mês (`meta`, `efetivado`, `pendente`, `total_mes`). |
| `savePlanejamento`                   | `salvar_planejamento`                  | Insere/atualiza um item em `planejamentos` (`usuario_id`, `ano`, `mes`, `categoria_id`, `subcategoria_id`, `tipo`, `valor_planejado`). Usa `ON CONFLICT` para não duplicar. |
| `updateValorPlanejado`               | `ip_prod_upsert_planejamento`          | Variante mais direta do `salvar_planejamento`: faz um **upsert** (insert ou update) de um único item de planejamento. |
| `copiarMesAnterior`                  | `ip_prod_copiar_planejamento_mes_anterior` | Duplica os registros de `planejamentos` do mês anterior (`ano/mes - 1`) para o mês atual, mantendo categorias/subcategorias e valores. |
| `repetirPeloAno`                     | (usa internamente `salvar_planejamento`) | Pega os planejamentos do mês atual e replica para os meses seguintes até dezembro (`mes+1 ... 12`). |
| `sugerirPorMedia`                    | `economia_categorias_ipoupei_2025`     | Calcula a **média histórica (últimos 3 meses)** de despesas/receitas por categoria. Sugere valores para metas (`valor_planejado`) de categorias sem planejamento. |
| *(auxiliar)*                         | `projecoes_mensais_ipoupei_2025`       | Gera **projeções** (baseadas em metas ou médias) para meses futuros, usado em dashboards/estatísticas. |

---

  SELECT
    tc.table_name,
    tc.constraint_name,
    tc.constraint_type,
    kcu.column_name,
    ccu.table_name AS foreign_table_name,
    ccu.column_name AS foreign_column_name
  FROM information_schema.table_constraints tc
  JOIN information_schema.key_column_usage kcu
    ON tc.constraint_name = kcu.constraint_name
  LEFT JOIN information_schema.constraint_column_usage ccu
    ON tc.constraint_name = ccu.constraint_name
  WHERE tc.table_name IN ('planejamentos', 'categorias', 'subcategorias', 'transacoes')
    AND tc.table_schema = 'public'

  -- Função ip_prod_upsert_planejamento
  SELECT
    routine_name,
    routine_definition,
    data_type,
    type_udt_name
  FROM information_schema.routines
  WHERE routine_name LIKE '%planejamento%'
    AND routine_schema = 'public';

| ip_prod_buscar_planejamento_mes          | 
BEGIN
    IF p_usuario_id != auth.uid() THEN
        RAISE EXCEPTION 'Acesso negado';
    END IF;
    
    RETURN QUERY
    SELECT 
        p.id,
        p.categoria_id,
        c.nome::TEXT,
        c.cor::TEXT,
        c.icone::TEXT,
        p.subcategoria_id,
        s.nome::TEXT,
        p.tipo,
        p.valor_planejado,
        p.created_at,
        p.updated_at
    FROM public.planejamentos p
    JOIN public.categorias c ON c.id = p.categoria_id
    LEFT JOIN public.subcategorias s ON s.id = p.subcategoria_id
    WHERE p.usuario_id = p_usuario_id
        AND p.ano = p_ano
        AND p.mes = p_mes
    ORDER BY c.nome, s.nome NULLS FIRST;
END;
